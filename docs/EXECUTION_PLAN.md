## 3. 本轮修复范围与验收目标

### A. 预览与隐私

- 修正 README 中手动预览和旧版迁移的服务器命令，显式绑定 `127.0.0.1`。现有 preview-web.ps1 已绑定回环地址，保留该边界。
- 根目录服务会映射被 Git 忽略的文件，文档应如实说明仅临时、本机迁移使用；不要宣称 gitignore 能保护 HTTP 文件访问。
- 复查所有即将提交的文件与本地可见 Git 历史，报告敏感信息扫描范围和结果；不输出或复制密钥内容。截图检查可见内容和元数据。
- 继续忽略 keystore、jks、keystore.properties、local.properties、构建产物、工作区私有配置和可能生成的备份/测试数据；按实际新增内容补规则，不把所有 JSON 一概忽略。

### B. 一键构建与安装脚本

- 修复 SDK 路径写入 local.properties 的转义。现有 `$SdkDir.Replace('\\', '\\\\')` 在 PowerShell 中不能替换普通路径中的单个反斜杠。验证应覆盖含空格及中文的路径，并检查实际解析结果，不能只检查文本中存在 sdk.dir。
- 在首次下载 Node 前创建所需目录，覆盖没有合格系统 Node 且 tools 目录不存在的场景。
- 将本项目镜像配置改为本次构建显式加载的独立配置，不再写入用户全局 `.gradle/init.gradle`。不得自行删除、恢复或重写机器上已有的全局配置；确实被全局配置阻断时报告证据。
- 保持 debug、release、-Install 入口及错误提示可用，保留 Windows PowerShell 5.1 所需编码和语法兼容。验证 -Install 可采用模拟；不得未经授权连接手机执行安装。
- 同步 package-lock 的项目版本元信息至 1.4.0，不借此升级依赖；保持 versionName 1.4.0、versionCode 7，本轮不擅自发新版本。

### C. 结束专注的保存失败与恢复

- 历史记录保存失败时，不得清除进行中的专注及其持久恢复状态，不得显示保存成功，应保留重试或导出的恢复路径。
- 保存成功但恢复状态清理失败、用户重复点击或重开重试时，不得重复记账。可选用稳定会话标识、可恢复提交状态等局部方法；不得只修提示文案。
- 用隔离存储分别注入历史写入失败和恢复状态清理失败，验证刷新/重开、重试后的记录数量与总时长。

### D. 跨零点的时长守恒

- 保留本次总时长不足 1 秒时不生成记录的原有产品规则。
- 总时长达到 1 秒时，跨日正时长分段不能因为各自不足 1 秒而被丢弃；分段毫秒和必须等于净专注总时长，日期与暂停扣除正确。
- 必测：23:59:59.400 至次日 00:00:00.600，合计 1200 ms，正分段之和为 1200 ms；另测正常跨日暂停与零时长分段。
- 统计计算、导出和再导入保留毫秒精度；界面如何显示不足一秒的分段可局部调整，但不得让用户误以为记录丢失。

### E. 编辑记录的确定规则

- 保留每条目标记录原始 startTs、endTs、date，禁止以新 durationMs 反推 endTs。
- 同 gid 编辑仍作用于整组，组内时长之和等于输入值，各条均满足 `0 <= durationMs <= endTs - startTs`。按原有效时长占比分配；若候选分配使任一分段超出原区间，拒绝整次编辑并提示，不自动溢出到其他日期。取整零头不得突破边界。
- 保留现有 24 小时输入上限。总量超限或分段容量不满足时，整次编辑不落盘，不允许先改名再报错。
- 对旧版本已经产生的异常历史记录，不自动改变起止时间和日期；如修复必须依赖有损迁移，先报告方案。不要为满足新校验静默删除或裁短既有数据。
- 必测：23:00—次日 00:00 和 00:00—01:00 两段各 1 小时，试改总时长为 6 小时应拒绝且所有字段不变；改为 90 分钟应成功、合计精确、时间区间不变。另测不等长分段与取整边界。

### F. 同源多个页面的数据覆盖

- 修复各页面持有陈旧 sessions 快照后整表覆盖导致丢记录的问题。不能仅增加 storage 事件监听或仅在写入前重新读取；读取、合并、提交必须有并发协调。
- 不同页面各自产生的记录都应保留；删除不能被另一个旧页面自动复活。编辑或删除同一条记录的冲突须有确定、可说明的处理，不能静默覆盖；可提示冲突并要求刷新后重试。
- 同一 origin 的进行中会话应保持一致，第二个页面不能无提示地覆盖第一个页面的会话。
- 优先局部方案；若环境不支持可靠协调，允许退化为明确提示的单写页面模式。不能宣称该环境支持多页面并发写入，也不能把所有环境永久限制单页来替代修复。
- 必须提供真实浏览器两个独立页面/上下文、共享同一 origin 存储的交错验证。只用内存 Map 或顺序调用函数不能证明此项通过。

### G. 导入与备份边界

- 加强导入校验，拒绝超出 JavaScript Date 范围的时间戳、不存在的日历日期及非法时间区间，坏记录不进入统计，合法记录照常合并，并报告跳过数量。缺失日期可从合法 startTs 补齐；已有合法 date 不因当前时区不同被自动改写。
- 保持合法历史备份的兼容性、同 id 合并和本机独有记录保留；异常旧数据需要有损处理时报告，不自行批量清洗。
- 本轮无需扩展备份格式来恢复 ongoing；在导出界面与文档明确「备份只含已完成记录和快捷事项，当前进行中的专注不包含，迁移/卸载前先结束并确认保存」。这是控制改动范围的实现选择，不增加自动结束行为。

## 4. 验证边界与实现自由

先复核发现是否仍存在，再实施局部修复；发现不成立时返回复现输入和实际结果，不机械修改。

可以增加小而有用的回归脚本。避免为了测试大幅改造单文件前端或引入庞大框架。测试数据必须为合成数据，不使用真实专注记录。构建输出和临时测试产物放在忽略目录。

普通计时、暂停/继续、恢复、记录编辑/删除、图表、导入/导出要做相关回归。原生通知、权限、进程恢复未经过真机检查时，只能列为待测，构建成功或网页通过不能代替真机验收。

首次安装工具链的验证要说明是隔离模拟还是全新 Windows 环境；在已有工具缓存的机器构建成功，不能证明冷启动下载路径通过。不得为了模拟空环境删用户工具目录或改全局 PATH。

返回材料以支持复核为准：

2. 相对接手时的补丁/变更文件；若指挥 AI 无共享目录，提供可还原成果的源码包，排除密钥、真实数据和缓存。

4. 必要复现脚本或测试命令；多页面项附真实浏览器交错步骤与结果，构建项附命令、退出状态和产物哈希。只截取与结论相关的短输出。
5. 仍存在的风险、真机待验项及阻塞原因。不要提交冗长全量日志。

对同一根因最多连续尝试 3 次有依据的修复/验证；没有新证据时停止重试。遇到必须有损迁移、改变已确定规则、缺正式签名、工具不可用或需要扩大架构范围，停止受影响部分并返回证据、已尝试办法、可选下一步。其余独立工作继续。

指挥 AI 收到实际产物和证据后，对每项判定通过、需要修改或证据不足。未验证不能记为通过；执行中新提出的偏好或可选优化不成为新增验收门槛。
